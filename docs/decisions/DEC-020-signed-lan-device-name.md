# DEC-020：发现阶段的设备名称

> 状态：Accepted
> 日期：2026-09-29
> 负责人：Linductor
> 工作项：M5-16

## 背景

Pinned Heyaki 的 `LanPresence` 不携带设备名。用户明确要求在设备发现时看到
对方设备名；改动 Heyaki 的通用发现协议会扩大依赖边界。

## 决策

Aki Adapter 在独立的 IPv4 组播地址 `239.255.42.98:49191` 发送有界
`AKINAME1` 报文：magic、Heyaki Ed25519 公钥、秒级时间戳、1–64 字节名称、
签名。接收端校验长度、时间窗口（±30 秒）、签名，并从公钥派生 DeviceId；
只有与 Heyaki 已发现设备的公钥一致才更新名称。广播和接收由 Executor 周期
任务承担，非阻塞 socket 每轮最多读取 32 包，关闭时取消定时句柄。局域网不
允许组播时，发现仍可按 Heyaki 身份运行，界面暂显 ID。

名称是对端声明、经身份签名绑定的展示元数据；本机备注单独存于 Aki 数据库，
不会广播，也不会被后续发现覆盖。用户设置的首启名称从本机设备记录读取，Settings 改名走同一字段级更新入口并热更新后续广播，
重启保持稳定。

## 验证与限制

编解码单测覆盖正常中文名、篡改和过期报文；双端真实组播可达、名称同步与
长名称布局需在 M5-16 验收中复测。名称广播不携带权限与信任状态。
