# X11 input method consumed key presses still reach the input widget

Pinned EUI-NEO v0.6.0 b9032a8, bundled GLFW X11 backend. Ubuntu 24 in a Wayland session, X11 backend selected with DISPLAY and XMODIFIERS=@im=ibus.

## Reproduction

1. Focus an input with already committed text.
2. Switch to Chinese IBus input and type a nonempty preedit string.
3. Press Backspace before committing the candidate.

Both the IBus preedit and the committed input text lose a character. Chinese character commits, image thumbnails and application identity otherwise work in the same user test.

## Source evidence

`3rd/glfw/src/x11_window.c` calls XFilterEvent first and retains `filtered`. In KeyPress with XIC, `_glfwInputKey` executes irrespective of `filtered`; only the later Xutf8LookupString/character dispatch is guarded by `!filtered`.

EUI's Linux ime_bridge is a no-op, so the existing Windows-style composition guard cannot distinguish this case. Public GLFW key callbacks do not expose XFilterEvent's result or the native XIC. Suppressing every Backspace while a Chinese engine is enabled would also break normal deletion after a commit.

## Minimal proposed correction

Gate the entire key dispatch/timestamp update block with `!filtered`, keeping character dispatch and duplicate suppression for delivered keys. A filtered initial event must not consume the timestamp of an unfiltered event forwarded later by asynchronous IBus. The forwarded event may carry the same timestamp.

The first Aki trial gated only `_glfwInputKey`, but still advanced `keyPressTimes`. The user then found ordinary Backspace stopped working in both English and Chinese modes. The revised build gates both dispatch and timestamp recording. On 2026-10-02 the user retested English deletion, committed Chinese deletion and preedit Backspace, reporting correct behavior.

The revised minimal patch is archived at [Aki PR #64](https://github.com/Linductor-alkaid/Aki/pull/64). It affects the generated build copy only. A regression harness compiles the actual patched dispatch block and checks filtered initial events, same-timestamp unconsumed forwarding, duplicate suppression, ordinary repeat and timestamp wrap. This changes consumed key delivery semantics and should be reviewed upstream, including consumers that intentionally need raw key events.

## Acceptance

IBus and Fcitx: composition Backspace/Enter/Escape/arrows only affect preedit/candidates; after commit ordinary Backspace edits the input once. English mode, modifiers, key repeat, focus changes and shutdown remain valid. Windows remains unaffected. Ubuntu 24 / IBus Backspace was manually accepted as above; Fcitx, candidate navigation, modifiers and focus changes have not been manually verified. Windows does not apply this patch.

Published as https://github.com/sudoevolve/EUI-NEO/issues/78 on 2026-10-01 after maintainer authorization. The configure-time build override now checks original, patch and output hashes and compiles the generated source. The corrected Backspace behavior was accepted on Ubuntu 24; the remaining manual matrix and latest CI are tracked in Aki PR #64.
